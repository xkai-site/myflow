# /notify 用户体验改造计划

## 目标
从普通 Pi 使用者的任务出发，把 `work/scripts/pi/pi-notification` 的 `/notify` 调整成「快速完成常用配置、少暴露内部术语、复杂设置可渐进发现」的入口；保留现有配置兼容性、会话/默认值语义和投递安全边界。

## 假设用户与 JTBD（待真实访谈验证）
- 主要用户：想在离开终端时知道任务完成/失败的 Pi 使用者，不一定了解渠道、阈值、配置 schema。
- 功能任务：确认通知是否启用；选择收到什么、发到哪里；验证确实可用；需要时减少打扰。
- 情绪/社交任务：对长任务结果有把握，避免错过失败；不想被配置细节和误报吓退。
- 当前痛点假设：术语、设置分类和三层配置语义占用认知；邮箱/webhook 配置门槛高；状态/测试“已提交”与“已送达”容易混淆。
- 当前收益假设：安全默认值、明确生效范围、一步测试、失败时给出下一步；高级项仍可达但默认不挡路。

## 原则
1. 剃刀原则：常用任务优先，只显示做出决定所必需的选项；不删掉必要的安全说明。
2. 渐进披露：日常开关/事件/渠道是一层；频率、静默、内容定制和诊断放到高级设置。
3. 面向结果而不是 schema：中文、可理解值与状态；避免将 JSON/内部 ID/层级放在主路径。
4. 可逆且透明：每项明确「仅本次对话」或「设为默认」；测试页说清提交不等于送达。
5. 不回归安全：凭据遮蔽、邮箱测试边界、强制静默、稀疏写盘与未知字段保留。

## 已定交互
- 首页：总开关、提醒时机、接收方式、测试通知、更多设置（5项）；不展示全局级别门槛、内容/安静时间、重试/队列、诊断/搜索。
- 更多设置：全局级别门槛、内容、免打扰时段、投递与频率；状态/诊断、重读、搜索放在该页。
- 通知场景行支持 Space 快速启停，Enter 仍打开详细字段；测试动作就近在首页，Ctrl+T 仍保留。
