# pi-notification：渐进式设置界面改造计划

> 状态：已获 Plannotator 批准，进入委派执行。模型固定为 cc-switch-deep-seek/deepseek-flash:high；父助手仅规划、协调与验收。

## Context

当前 `/notify` 将配置字段平铺为长列表，重复分组前缀、`✓ false`、技术枚举和大量“未保存”增加理解成本；值贴终端右边导致阅读距离过长。

目标：采用“常用首页 → 分类页 → 详情”的信息架构，常用操作直接可达，复杂参数按需展开。改造分三阶段验收，不改变通知判定与投递策略。

本计划是 `plans/pi-notification-ux.md` 的后续改造：替代其平铺列表、全量默认值列和仅快捷键可发现的动作入口；保留单入口、三层配置、会话隔离、单项保存、脱敏与失败不回滚等约束。

## Approach

- 第一阶段先修复文案、布局、来源表达和操作反馈，保留现有列表结构。
- 第二阶段引入首页、分类、规则详情和条件展开；不使用双栏布局，不引入浏览器 UI 或额外依赖。
- 第三阶段增加搜索、示例预览、单项恢复与诊断，优先复用已有配置、正文生成和状态能力。
- 显示中文，但内部配置键、枚举值、单位和配置格式保持不变。
- 修改立即影响本对话；Ctrl+S 只将明确的当前配置项设为以后默认。导航行、动作行不得触发隐式批量保存。
- Esc 返回，不撤销已生效的修改；隐藏字段不清空值。
- 渠道凭据、URL、headers 不进入界面或预览。非 TUI 仍只读。

## 已发现的实现基础与风险

- `src/ui.ts` 已有 list/detail/input/status 状态、12 行分页、渲染缓存、宽度裁剪、候选选择与输入校验入口，可演进为带返回位置的导航栈。
- `src/settings.ts` 的 `buildSettingItems` 是字段描述表，包含稳定 ID、读取/写补丁、候选值、格式化与解析，继续作为字段唯一来源。
- `src/commands.ts` 的 `createSettingsHost` 隔离 UI 与持久化；已有 overlay、强制静默判断、测试、重读、状态入口。
- UI 当前只拿到生效配置与用户原始配置，不能仅通过“值是否相等”可靠判断本对话覆盖来源；需要增加只读来源信息。
- 普通字段保存使用稀疏补丁；渠道保存当前从生效配置构造整个 providers 数组，可能带入其他渠道的本对话开关。需核验并以“保存一个渠道不固化其他渠道临时选择”的回归约束修正，而非沿用这一副作用。
- `test/settings-ui.mjs` 已有真实按键字节、stub host、临时用户目录和显示列宽测试；部分断言明确要求旧文案，需替换而非机械保留。
- `package.json` 已有 UI、patch、config、host、CLI、service 等测试脚本，无需新增测试框架。
- 已确认空 overlay 风险：`extensions/index.ts` 的 `persistOverlay` 跳过空值，`settings.ts` 恢复逻辑也跳过空快照。恢复最后一项必须同时修复这两个边界，用合法空快照表达清除，避免恢复旧值。
- `config.ts` 的 `checkProviders` 对缺失 `enabled` 默认取 true；恢复渠道开关应仅删除该 provider 的 enabled，保留 id/type/options/其他渠道，不删除整个 provider。详情明确“渠道开关内置默认：开启”，不承诺删除自定义渠道。
- `config.ts` 已有私有 `atomicWriteConfig`。单项删除应在同模块复用该原子写入能力，先读原始稀疏文件、删除、校验、成功写盘，再更新 overlay；缺失文件且无待删字段时不必创建配置文件。
- `rules.ts` 的 `evaluateRunOutcome` 可用固定 RunOutcome/RunSummary 生成示例正文；克隆配置并仅为示例开启完成规则，标记为内容示意，不提交 service。通知实际可发送状态独立说明。
- 工具失败阈值在 aggregate 模式中也用于 fallback 判断，不能随该模式隐藏；只有 toolFailureWindowMs 属于 immediate 专用。`extensions/index.ts` 对 immediate 按单工具累计次数判断阈值；aggregate 按本运行失败总次数判断阈值，帮助文案分别说明。
- 服务的 `snapshot` 是累计统计而非测试通知的专属回执；某些不可用渠道通过 noop 跳过。诊断不得凭 delivered 增加就宣称用户看到了测试通知，只展示观测事实与静态阻止原因。
- 当前 `git status --short` 仅有本计划文件未跟踪，无已有代码改动。

## 目标界面与交互契约

```text
通知设置

  启用通知               开启
  通知门槛               所有等级
→ 通知规则               完成、失败等事件       ›
  通知内容               耗时、会话名等         ›
  免打扰                 未开启                 ›
  通知渠道               1 个已启用             ›
  高级设置               频率限制与投递         ›
  发送测试通知
  状态与诊断                                  ›
```

- 内容区以约 80 显示列为上限，随终端宽度缩小；窄屏依次省略摘要、来源附注，再截断标签/值；详情保留完整信息。沿用现有分页，不依赖全屏双栏。
- 首页最多上述 9 项；“重新读取配置”放入状态与诊断，“通知预览”放入通知内容。
- ↑↓ 移动、PageUp/PageDown 翻页、Enter 打开/确认、Space 快速切换布尔或集合成员；Esc 返回并恢复焦点，首页 Esc 关闭。布尔 Enter 可进入字段详情以查看来源与恢复操作。
- Ctrl+S 始终保存当前字段的已生效值，不保存光标悬停但尚未选择的候选值；分类、动作、搜索输入及自定义输入不执行保存。自定义输入先 Enter 应用，再保存。
- Ctrl+T/R/O 保留在非文本编辑视图；文本输入视图不触发外发动作。全局快捷键不注册。
- 第三阶段首页增加可见“搜索设置”入口（不超过 10 项），同时支持 `/` 进入搜索。搜索覆盖完整字段表；未启用功能的字段可定位、预配置，并显示尚未生效原因，不能为了定位自动开启功能。
- 恢复操作放在字段详情的独立动作区；来源、以后默认与本对话覆盖分开表达，强制静默/配置降级显示为额外限制，不冒充用户选择。
- 通知规则关闭、全局关闭时不自动禁用编辑子项；动态刷新后目标字段/渠道消失时返回最近有效父级，避免焦点误落到其他设置。

## 已确认决策与预览约定

1. 第三阶段只提供单项恢复，不提供分类或全局重置；“沿用以后默认”只清除此项本对话覆盖；“恢复内置默认”在明确确认后同时清除此项用户默认与本对话覆盖。
2. 预览只在用户主动进入预览页面后生成固定示例，不在首页常驻，不读取真实对话、不外发；真实发送保持独立动作。

用户已明确确认单项恢复及“恢复内置默认”的双层清除语义。预览按前述推荐方案纳入整体计划审核。
