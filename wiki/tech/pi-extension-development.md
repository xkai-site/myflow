# Pi 插件开发与维护

本页说明插件共用的目录职责与维护要求。选择插件从[仓库插件索引](../../README.md#插件)进入；功能、安装、配置、依赖版本和测试命令由各插件目录内的 README、包清单及源码维护。

## 目录与职责

插件放在 `work/scripts/pi/<插件名>/`，以单个插件目录作为使用、测试和维护边界。按实际功能组织文件，`src/`、`docs/` 等目录在有对应内容时创建：

```text
<插件名>/
├── package.json       # 入口、依赖、兼容范围和测试命令
├── README.md          # 功能、安装、配置、开发与测试说明
├── LICENSE            # 独立分发所需的许可证
├── extensions/        # 宿主加载入口与注册逻辑
├── src/               # 按职责拆分的实现（按需）
├── test/              # 测试与本插件的测试辅助
└── docs/              # 较长的架构或协议说明（按需）
```

- 入口位置由 `package.json` 的 `pi.extensions` 声明。维护时将注册和宿主连接放在入口，复杂逻辑按配置、状态、外部访问、交互等职责拆分，模块划分以实际调用关系为依据。
- 每个插件随包维护自身源码、测试辅助和本地说明，相对导入与本地文档链接均位于插件目录内。小型辅助代码由使用它的插件维护；需要共享的能力通过发布包并声明依赖引入。
- 包清单中的 `dependencies` 声明运行依赖，`devDependencies` 声明开发依赖，`peerDependencies` 声明由 Pi 宿主提供的包。直接使用的宿主包逐项声明，由宿主提供实现。兼容范围记录在包清单中，实际验证版本记录在运行报告中。

## 配置、状态与资源

配置说明列出文件位置、默认值、生效时机、覆盖顺序，以及临时修改和持久保存的范围。读取失败、非法输入和保存失败时，说明保留原数据的方式、错误反馈和恢复步骤。

凭据说明交代读取来源、存储形式、发送目标和失败结果。日志与错误信息中的密钥必须脱敏。可分发默认配置使用无账号信息的模板，用户配置、运行状态和恢复记录按各自用途存放。

资源维护按用途区分：

- 会话中的请求、计时器和发送队列按调用需要创建，在取消、会话切换或退出时按所属生命周期取消或释放。异步任务和重试明确所属会话及状态的有效范围。
- 外部访问说明超时与取消方式、退出前最多等待多久，以及等待超时后如何处理剩余工作。本地取消或超时后的远端任务状态与费用核查，由插件说明调用方责任。
- 用于后续查询或下载的持久化恢复记录按任务结果清理。插件说明保存位置、恢复所需配置和移除条件；会话结束与任务记录清理分别处理。
- 交互说明分别列出终端界面中的操作，以及非交互运行时的可用入口、输出与失败结果。

## 测试与验证

从[插件索引](../../README.md#插件)打开目标 README，在该插件目录按“测试”或“开发与测试”说明准备依赖，并运行 `package.json` 中的对应命令。

根据功能选择验证层次：

| 层次 | 核对重点 |
| --- | --- |
| 模块测试 | 输入校验、状态变化、配置合并、边界条件与失败路径 |
| 外部交互测试 | 使用本机服务、可控的模拟服务或模拟响应验证协议、超时、重试、取消及脱敏 |
| 宿主集成测试 | 在目标宿主版本中核对加载、注册、事件、输出与资源释放 |
| 独立性验证 | 将插件复制到仓库外，按自身文档准备依赖，核对加载、测试和本地引用均能在独立目录中使用 |

自动测试优先使用临时目录、模拟凭据和可控响应，将个人配置与真实付费服务留给另行授权的验证。需要 Pi SDK（供测试创建宿主会话的开发接口）、宿主程序或系统能力时，插件的测试说明列出自动定位方式、通过参数或环境变量指定实际安装位置的方法，以及前置条件和跳过条件。

模拟测试的结论限定在受控输入与响应下；真实服务、账号权限、最终投递和类型检查分别验证。运行报告记录命令、工作目录、源码版本、环境、退出状态与未覆盖范围，兼容性结论限定在实际验证的版本和环境。

## 修改与文档维护

1. 修改前阅读目标插件的 README、包清单、入口和实际调用模块。
2. 修改后运行受影响的专项测试；涉及宿主接口、安装或目录依赖时，补充集成或独立性验证。
3. 用户入口、配置、权限、输出、依赖或测试方式变化时，同步更新该插件内的使用说明和架构文档。
4. 共用目录职责或维护要求变化时更新本页。

仓库整理或集中验证的记录放在 [`work/tasks/`](../../work/tasks/)。报告关联当时的命令、环境和源码版本；对照历史材料时固定源提交，复跑结果写入新的报告路径，原始记录按当时环境保留。
